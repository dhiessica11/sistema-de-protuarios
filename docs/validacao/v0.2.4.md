# Validação — v0.2.4

Data: 2026-11-03. Escopo: leitura de chaves binárias e Compose completo de desenvolvimento.

## Correções

- Segredos Docker são lidos integralmente com `read_bytes()`, sem `.strip()`.
  Espaços e quebras de linha nas extremidades dos 32 bytes são preservados.
- 35 testes de regressão cobrem as cinco chaves, cifra/decifra, tamanho inválido,
  ausência de fallback silencioso e leitura de desenvolvimento.
- Dockerfile instala as dependências com hashes e aceita uma CA opcional via
  segredo BuildKit `proxy_ca`, somente durante o passo de instalação. Não desabilita
  TLS nem copia o certificado para a imagem.
- Compiladores e cabeçalhos PostgreSQL removidos da imagem: o lock instalado usa
  psycopg-binary e wheels compatíveis. libmagic e curl permanecem instalados.
- `.dockerignore` exclui caches, banco local, arquivos estáticos e ambientes virtuais.
- Healthcheck do PostgreSQL especifica o banco correto. SQL de inicialização é
  montado somente para leitura, com diretório 0755 e arquivo 0644 no pacote.

## Resultados executados

- Build das imagens web e worker, Python 3.12: OK.
- Compose: db e redis saudáveis; web e worker em execução.
- PostgreSQL 16: migrations aplicadas; extensões citext, pgcrypto e uuid-ossp confirmadas.
- Testes dentro de web, com PostgreSQL e configurações dev do Compose:
  **74 passaram**, cobertura **78,36%**, acima do mínimo de 70%.
- Ruff lint limpo; 36 arquivos formatados; `pip check` sem incompatibilidades.
- Migrations sem drift; Django system check sem problemas.
- Auditoria do lock executada dentro do container: nenhuma vulnerabilidade conhecida.
- Bandit no filtro do CI (`-ll`): nenhum achado médio/alto.
- HTTP real em `http://127.0.0.1:8000/health/`: 200 e JSON esperado.
- Login e página Admin pelo Django Test Client: 200; apenas Grupo, Usuário e Clínica
  registrados. Usuário sintético criado dentro de transação revertida.
- Worker respondeu a ping e executou `celery.accumulate` via Redis. Resultado recebido
  pelo cliente e removido depois da verificação; execução eager não foi utilizada.
- Arquivo binário sintético real em `/run/secrets/prontuario_key_a` dentro de web:
  conteúdo integral confirmado e cifra/decifra concluídas. Arquivo removido ao final.

## Ambiente e limites

O ambiente gerenciado usa Docker com driver vfs e disco limitado. A primeira
tentativa de subir os containers ficou sem espaço. Cache e imagens intermediárias
desta tarefa foram removidos e a imagem foi reduzida antes da execução bem-sucedida.
O Compose final subiu os quatro serviços em conjunto.

Foi usado um override temporário de Compose apenas para fornecer a CA do proxy:
segredo de build e montagem de CA somente leitura para a auditoria HTTPS. Não foi
alterada a topologia, banco, comandos de serviço ou modo de execução das tarefas.
Esse override e o certificado não integram o pacote nem o repositório.

Não foram usados dados reais. A validação é do Compose de desenvolvimento,
não de um ambiente de produção, nem da máquina da desenvolvedora. A aplicação
continua sem MFA efetivo, assinatura gov.br, auditoria clínica completa e demais
controles previstos nos lotes seguintes. Persistem avisos de factories e paginação
sem ordenação; não impedem esta validação.

## Reproduzir localmente

Seguir INSTALAR.md, gerar chaves dev, preparar `.env`, então:

```bash
docker compose up -d --build
docker compose exec -T web python manage.py migrate --noinput
docker compose exec -T web pytest --cov=apps --cov=config --cov-fail-under=70
docker compose exec -T web ruff check .
docker compose exec -T web ruff format --check .
docker compose exec -T web pip check
docker compose exec -T web pip-audit --strict --require-hashes --disable-pip -r requirements-dev.lock
docker compose exec -T web python manage.py makemigrations --check --dry-run
curl --fail http://localhost:8000/health/
docker compose exec -T web celery -A config inspect ping
```

Detalhes do formato das chaves em `docs/CHAVES.md`. Registros de teste e auditoria
desta versão acompanham este relatório.
