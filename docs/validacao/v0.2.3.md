# Validação — v0.2.3

Data: 2026-11-03. Escopo: correção das dependências sobre a v0.2.2.

## Alterações

| Pacote | Antes | Agora |
|---|---|---|
| Django | 5.1.15 | 5.2.18 (LTS) |
| Django REST Framework | 3.15.2 | 3.18.3 |
| PyNaCl | 1.5.0 | 1.6.2 |
| pytest | 8.3.5 | 9.2.0 |
| pytest-django | 4.9.0 | 4.14.0 |
| pip | 25.0.1 | 26.3 |

Setuptools 84.2.1 foi incluído no lock para evitar também as vulnerabilidades
detectadas na versão 82.0.1 durante a atualização. Build backend exige a faixa
corrigida. Pip-tools 7.6.2 gera as versões exatas e hashes das dependências diretas,
transitivas e ferramentas em `backend/requirements-dev.lock`.

Docker e CI instalam o lock com `--require-hashes` e depois o projeto local com
`--no-deps --no-build-isolation`. A auditoria do CI usa o lock completo e não ignora
falhas. A configuração de arquivos estáticos migrou para `STORAGES`, compatível
com Django 5.2, preservando WhiteNoise.

## Verificações executadas

- Instalação do lock com verificação de hashes em ambiente virtual separado.
- `pip check`: nenhuma incompatibilidade.
- `pip-audit --strict --require-hashes --disable-pip -r requirements-dev.lock`:
  **nenhuma vulnerabilidade conhecida encontrada**.
- SQLite: **39 testes passaram**; cobertura **78,74%**.
- PostgreSQL 16 em container local: migrations aplicadas e **39 testes passaram**.
- Ruff: lint limpo; 35 arquivos com formatação conforme.
- Django: sem drift de migrations; system check sem problemas.
- Bandit no nível exigido pelo CI (`-ll`): sem achados médios/altos; 49 baixos.
- `collectstatic`: 154 arquivos copiados e 444 processados; backend WhiteNoise
  confirmado via registro de storages.
- Health via Django Test Client: 200 e JSON esperado.
- Admin registra apenas Grupo, Usuário e Clínica.

## Limites e próximos passos

Validação com Python 3.12.14 em Linux; PostgreSQL em Docker. O Compose completo,
o build das imagens e a execução no computador da desenvolvedora ainda não foram
validados. O workflow foi alterado, mas não foi executado no GitHub.

Os avisos de paginação sem ordenação e de factories permanecem. A correção da
leitura de chaves binárias Docker (`.strip()`) continua pendente e não faz parte
desta atualização de dependências. Não foram alterados modelos, regras de negócio
nem migrations.

O resultado de auditoria vale para o catálogo consultado nesta data e não é uma
aprovação geral da segurança do sistema. O relatório v0.2.2 permanece como
registro histórico do estado anterior.
